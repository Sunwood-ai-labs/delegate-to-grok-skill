# 実行契約

このラッパーは、プロンプト、権限、ワークスペース範囲、認証、Grok CLI の単一実行がどう動くかを定義し、委譲を予測可能にします。

## タスク境界を定義する

すべてのヘッドレス実行で `scripts/invoke-grok.ps1` を使います。短い再試行でも `grok -p` へフォールバックしません。タスク全文を 1 つの `-Prompt` に渡し、ラッパーに UTF-8 の一時ファイルとして Grok へ渡させます。

既定は読み取り専用です。ラッパーは読み取り専用サンドボックス、既定権限、Grok 内サブエージェント無効、メモリ無効、指定ディレクトリ限定を設定します。書き込みにはユーザーの明示依頼と `-AllowWrites` が必要です。

## セッションを一貫させる

ラッパーはタスクの前後で `grok models` を確認します。明示的なログイン確認とモデル一覧の両方がある場合だけ成功と判断します。名前付きミューテックスが 2 つ目のラッパープロセスによる認証競合を防ぎます。

認証が明示的に欠けている場合、対話的な `grok login --oauth` を 1 回だけ実行し、`grok models` で確認してください。正規の認証ファイルを読んだり修復したり公開したりしないでください。

## 所見を Codex に戻す

ユーザーが許可した書き込みタスクの前に、リポジトリ指示と `git status --short` を記録します。後で完全な差分を確認し、適切なテストを独立して実行します。ラッパーは commit、push、login、logout、権限プロンプトの迂回を行いません。

公開 X 調査では直接 URL を収集しますが、投稿や反応はしません。Grok の出力は証拠として扱い、時事性または高リスクの主張は一次情報で独立して検証してください。
